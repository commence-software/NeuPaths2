for distributed software The architecture of a broker-less dataflow framework, in UML.

Most distributed systems have a thing in the middle — a broker, a queue, a coordinator that every signal passes through. NeuPaths removes it. Autonomous cells wired by synapses pass typed stimuli across a mesh with no center, processing in parallel wherever data arrives.

Four commitments that shape everything

01 · No center

No server, queue or coordinator class exists. Every cell carries its own Nuc_Nucleus and talks peer-to-peer. Resilience is a property of the mesh's shape, not of a component.

02 · Dataflow

An activator runs only when all receptors are full. Timing is dictated by data arrival; between stimuli, threads sleep on OS wait-queues — no polling, no spinning.

03 · Location transparency

A cell neither knows nor cares whether a peer is in the same JVM or across a datacenter. One synapse-name string hides every transport difference.

04 · Self-contained

Pure Java SE — no native code, no third-party dependencies. It deploys as a single JAR and adds no operational surface of its own.

01Architecture

The anatomy of one cell

Every cell has the same internal shape regardless of type. You supply the Activators; the framework supplies the Nucleus and its transport. A cell is a complete, self-routing participant in the mesh.

Why remove the broker

The broker is where the hardest problems concentrate — the thing you keep alive, keep scaled, keep from becoming the single point of failure. With no center, there is nothing to provision or babysit, location stops mattering to your code, and resilience comes from the mesh's shape: run an activator on two nodes, let stimuli travel more than one path, and the Nucleus's duplicate filtering makes the redundancy safe.

Deployment

A system is a set of JVM processes, each hosting one CellCluster, wired into a mesh by synapses. Any process can host any cells. The CellClusterDaemon is an optional operational convenience — not a broker: it deploys and controls clusters, but no application traffic flows through it.

The dataflow contract

evaluate() is called by the cell's activator thread only once all receptors are non-empty. The activator reads inputs with getStimulus(), computes, and emits with setStimulus(). Between firings the thread sleeps on a semaphore. Subclass Activator, EventActivator, PulsedActivator or LoadBalancedActivator.

Subscriptions — the wiring contract

A subscription is the contract (producing cell C, transmitter T) ⇒ receptor R, tagged with a domain. C and T may be regular expressions, so one receptor can aggregate stimuli from many producers.

Stimulus — the atomic data unit

Stimulus is abstract and Serializable. Each instance carries type identity (typeID, a fixed UUID), a unique instanceID, an optional transactionID, and producer/consumer metadata the framework fills in as it travels. The neupaths.stim package ships eleven ready-made primitives:

03Subsystems · internals

Beneath the API

Six internal subsystems, each named by a class prefix: Nuc_ nucleus, Syn_/Bnd_ transport, Cryp_ crypto, Msg_ protocol, Cfg_ configuration.

The Nucleus — per-cell routing engine

This is what replaces the broker. Every cell carries one. It owns the cell's binders, matches incoming stimuli against subscriptions, filters duplicates, re-advertises interest to peers, and runs the send/receive worker threads.

Transport — synapses & binders

Two cooperating hierarchies. Synapses are the raw channels (an abstraction over a JDK NIO channel); binders manage the peer relationship and message framing over a synapse. A Listener spawns a fresh peer synapse each time a Peer joins.

Cryp_* · cryptography

A pluggable Cryp_Cipher encrypts each stimulus into a SealedObject. The factory reads a type byte from the key: Cryp_AES (AES/CBC) or Cryp_Blowfish. Cryp_Null is pass-through; Cryp_Stim is a fixed-key default. Strategy + Factory.

Msg_* · wire protocol

Everything crossing a synapse is a Msg_NeuPaths. Msg_Stimulus is the data plane; Msg_JoinRequest/JoinAcknowledge, Msg_Subscription and Msg_Leave are the control plane for the broker-less mesh.

Cfg_* · configuration

Clusters and cells are declared in XML and parsed by a recursive DOM handler tree (Cfg_ConfigHandler → per-cell handlers). Callback interfaces aggregate children upward; reflection instantiates activators and reads each stimulus TYPE_ID.

util · daemon control plane

The CellClusterDaemon is itself built from cells: DaemonCmdActv in a LogicCell processes DaemonCmdStim commands. IssueCommandToDaemon talks to it as an ordinary NeuPaths client — no privileged backchannel.

Exception hierarchy

Two roots: a checked Excp_NeuPaths family used internally, and a single unchecked NeuPathsException surfaced to callers. Excp_SynapseFatal vs Excp_SynapseNonFatal lets the transport tell a dead connection from a recoverable hiccup — key to mesh resilience.

Peer join handshake

When a Peer contacts a Listener they perform a two-phase join, then exchange subscriptions so stimuli can flow. This is the decentralized replacement for "register with the broker."

End-to-end: Injector → Logic → Extractor

Built-in control plane

Two behaviors run without any user code. Cycle detection — an Actv_CycleDetection is added to every cell; a probe stimulus accumulates a trace, and a cell that sees itself already in the trace raises Stim_CycleDetected. Load balancing — workers register with a LoadControllerCell and poll for a work signal; the controller hands the next stimuli set to exactly one worker, spreading load with no central queue.

05Execution model · threads & dataflow

Parallel by nature, asleep when idle

NeuPaths is thread-per-role, not thread-per-request. A stimulus is handed across a series of in-memory queues, each owned by a dedicated thread. Independent stages and independent cells run at once; every consumer blocks on a semaphore until work arrives — no polling, no spinning.

The handoff idiom

Every stage boundary is the same construct: a LinkedList guarded by a fair ReentrantLock(true), paired with a counting Semaphore(0, true) that signals "data available." The producer enqueues under the lock and calls release(); the consumer calls acquire() — parking there when the queue is empty — then dequeues. Because the consumer sleeps inside acquire(), an idle cell burns no CPU; fairness preserves FIFO order within each queue.

Thread inventory

Threads present in one running cell. A cell with A activators and P live peer connections runs roughly A activator threads + 4 nucleus threads + per-binder threads. Every cell auto-adds a cycle-detection activator, so A ≥ 1 always.

The dataflow gate

Incoming stimuli land in an Rx_Transaction — a bundle of receptors keyed by transactionID. Each stimulus fills its matching receptor; evaluate() runs only when every receptor holds a stimulus. Keying by transaction means several half-complete input sets can be assembled concurrently — a neuron waiting on three signals can hold multiple partial bundles in flight, each completing independently.

Guarantees & sharp edges

Ordering & parallelism

FIFO within one activator's queue; no global order across activators or cells. Activators in a cell evaluate concurrently, and independent cells share no state.

No backpressure

All queues are unbounded LinkedLists. A slow activator grows its own queue without throttling upstream — watch this under sustained overload.

Pause accumulates

pause() stops the activator thread consuming, but the Nucleus keeps receiving — so stimuli pile up in queues while paused, then flush on resume().

Shutdown & daemon threads

stop() sets terminate flags and interrupt()s each thread out of acquire(). Threads are daemon by default unless NEUPATHS_FORCE_GRACEFUL_TERMINATION is set.
